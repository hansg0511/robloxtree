# Studio-owned world manifest

`Workspace` is intentionally outside the Rojo mapping. It contains the visual map and heavy Studio artifacts that should be positioned and edited in Studio rather than regenerated by source sync.

Known world components include:

- `Workspace.PlayerPlots`, created and populated at runtime by `ServerStorage.PlotManager`.
- The mountain background and repeated environmental props.
- Forge, Anvil, Crafting Table, Platform, and visual-effect content.
- Terrain, CSG/UnionOperation content, meshes, and local world placement.

Tree gameplay crosses the boundary: `Trees/BuildTreePlots.server.luau` assigns player plots; `ServerStorage.PlotTemplate`, `PassivePlotTemplate`, and `TreeTypes` are Rojo-mapped source artifacts; the instantiated models appear under `Workspace.PlayerPlots` at runtime.

When an LLM needs to change gameplay, prefer updating scripts, templates, and configuration in `src/`. When it needs to change the physical level, author in Studio, save a backup, then refresh the relevant review manifest or deliberately add a narrowly scoped Rojo mapping later.
